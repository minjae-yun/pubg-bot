# DROPLOG v2 디자인 핸드오프 (Codex 구현용)

- 디자인 시안: `web/design/mockup-v2.html` (브라우저로 바로 열림, 예시 데이터)
- 현재 실제 사이트: `web/public/index.html` + `web/server.js` (읽기 전용 API)
- 시안의 `MOCK` 객체 모양을 그대로 API 응답으로 맞추면, 렌더 함수는 거의 그대로 재사용할 수 있음

---

## 0. 공통 규칙

### 라우팅 (뒤로가기 버그 수정)
- 지금 사이트는 화면을 `display` 토글로만 바꿔서 브라우저 히스토리가 안 쌓임 → 뒤로가기 시 사이트를 나감
- 시안은 **해시 라우터** 사용. 화면 전환 = `location.hash` 변경, `hashchange` 이벤트에서 렌더
- 라우트

| 주소 | 화면 |
|---|---|
| `#/` | 홈 |
| `#/player/:accountId` | 대원 |
| `#/match/:matchId` | 경기 상세 (기존 화면 유지, 상단에 맵 아트/스크린샷 추가) |
| `#/rank` · `#/rank/teamkill` | 랭킹 (미션 포인트 / 팀킬 비중) |
| `#/weapons` | 총기 |
| `#/highlights` | 하이라이트 |
| `#/patch` · `#/patch/:index` | 패치노트 |

- 모든 내부 이동은 `<a href="#/...">`로. 버튼 `onclick`에서 화면만 바꾸는 방식 금지
- 라우트가 바뀌면 `window.scrollTo(0,0)` 후 `initMotion()` 재실행 (ScrollTrigger 전부 kill 후 다시 생성)
- (선택) History API(`/player/xxx`)로 바꾸려면 `server.js`에서 `/api/` 외 경로는 전부 `index.html`을 주도록 폴백 추가

### 디자인 토큰 (Discord DESIGN.md 기반, 기존 그대로)
- 배경 `#0a0d3a`, 카드 `#1e2353`, 강조 Blurple `#5865f2`, 핑크 `#ec48bd`, 최고 우선 CTA만 Green `#35ed7e`
- 모서리: 컨트롤 12–16px, 카드 40px / 폰트: Pretendard, 제목 800–900
- **차트 전용 팔레트** (남색 배경 `#1e2353` 기준 색약 검증 통과, 이 순서 고정)
  - series-1 `#6f79f2` = 해당 대원
  - series-2 `#d64aa6` = 스쿼드 평균 (점선으로도 구분)
  - series-3 `#1f9e5f` = 세 번째 계열이 필요할 때만
- 버프/너프 같은 상태는 색만으로 구분하지 말고 기호 + 글자 같이: `▲ 버프` `▼ 너프` `● 변경` `↺ 복각`

### 모션
- 기존 `initMotion()` 유지: `[data-reveal]` 등장, `[data-count]` 카운트업, `[data-width]` 막대 채우기
- 목록/필터 갱신 시 `tweenIn()` 사용 (CSS transition과 GSAP 충돌 방지용, 이미 구현됨)
- `prefers-reduced-motion`이면 모든 애니메이션 끔 (이미 처리됨)

## 1. 홈 `#/`

| 섹션 | 내용 | 데이터 |
|---|---|---|
| 히어로 + 검색 | 기존과 동일 | `/api/players` |
| 이달의 MVP 배너 | 이번 달 미션 포인트 1위, 남은 기간, 랭킹 링크 | `/api/missions/leaderboard?month=YYYY-MM` 1위 |
| 최근 경기 (사진 카드) | 카드 상단 16:9 이미지 영역 + 순위 크게 + 치킨 배지 | `/api/matches/recent` + 스크린샷 |
| 새 하이라이트 | 2장씩 보이는 슬라이더 | `/api/highlights?limit=4` |
| 최신 패치 요약 | 제목, 태그, "우리 스쿼드 영향" 한 줄 | `/api/patches?limit=1` |

### 최근 경기 이미지 규칙
1. 그 경기에 업로드된 스크린샷이 있으면 첫 장을 `object-fit: cover`로 사용
2. 없으면 `mapArt(map, matchId)`로 생성한 지형 일러스트 사용 (공식 맵 이미지는 저작권 때문에 쓰지 않음)
   - 사녹: 초록 계열 + 강, 태이고: 주황 계열 + 도로. `matchId`를 시드로 써서 경기마다 모양이 다름
3. 스크린샷이 있으면 카드 본문에 `📷 스크린샷 N장` 칩 표시

## 2. 대원 `#/player/:id` (기존 화면에 추가)

### 실력 변화 그래프
- 형태: 주간 꺾은선, **y축 하나**, 지표는 탭으로 전환 (평균 딜량 / K/D / TOP 10). 두 지표를 한 차트에 같이 그리지 말 것
- 계열 2개: 대원(실선 2.5px, 점 표시) vs 스쿼드 평균(점선 2px). 끝점에 값 직접 표기
- 호버: 세로 크로스헤어 + 툴팁(해당 주 두 값)
- 아래 한 줄 요약: "첫 주 대비 +54 · 스쿼드 평균보다 94 높아요"
- API 제안: `GET /api/players/:id/trend` → `{ weeks:["08.30",...], me:{adr:[],kd:[],top10:[]}, squad:{adr:[],kd:[],top10:[]} }`
- 집계: `match_players` + `collected_matches`, **한국시간 기준 주(월요일 시작)**로 묶기. 경기 5판 미만인 주는 점을 비우거나 연결선만 표시

### 주력 총기 (상위 4개)
- 총기명, 분류(AR/DMR…), 킬 수, 1위 대비 막대

### 팀킬 기록
- 큰 숫자 = 팀킬 비중 % = 팀킬 ÷ (적 킬 + 팀킬)
- 보조: 팀킬 횟수, 최근 팀킬(날짜·맵·무기), 가장 많이 당한 대원

## 3. 랭킹 `#/rank`, `#/rank/teamkill`

### 미션 포인트 (기본 탭)
- 상단 바: 시즌 이름, 종료까지 남은 시간, 탭 전환
- 1~3위 시상대(가운데가 1위, 모바일은 1·2·3 세로), 4위부터 목록(포인트 막대 포함)
- 시즌 보상 카드 3개 + 명예의 전당(역대 월간 1위 가로 스크롤)
- **디스코드 ID 대신 이름으로 표시하는 방법**
  - `mission_completions.discord_user_id` → `registered_players.discord_user_id`로 조인 → `display_name`(없으면 `pubg_name`)
  - 같은 디스코드 ID가 여러 서버에 등록된 경우가 있으니 `discord_user_id` 기준으로 먼저 합치기
  - 포인트 = `mission_completions` JOIN `party_missions`(session_id, mission_key) 의 `reward_points` 합
  - 월 기준 = `completed_at`을 한국시간으로 바꾼 뒤 `YYYY-MM`
- API 제안: `GET /api/missions/leaderboard?month=2026-10` → `[{ name, accountId, points, missions }]`, `GET /api/missions/hall-of-fame`

### 보상 제안 (비용 거의 없음, 봇으로 자동화 가능한 것 위주)
| 순위 | 보상 |
|---|---|
| 1위 · 이달의 MVP | 디스코드 역할 "이달의 MVP" + 전용 이름 색(한 달), 사이트 금테 프로필 + 명예의 전당, 다음 달 미션 1개 직접 지정권, 킬내기 드래프트 1픽 |
| 2위 | 역할 "실버 스쿼드", 서버 커스텀 이모지 1개 제작권, 은색 배지 |
| 3위 | 음성 채널 이름 1주 변경권, 동색 배지, 하이라이트 메인 고정 1회 |
- 상품(기프티콘 등)은 스쿼드가 원하면 1위에만 추가. 매달 1일 00:00(KST)에 봇이 역할을 자동으로 회수·부여

### 팀킬 비중 탭
- 대원별 가로 막대 (막대 색은 series-2 핑크), 오른쪽에 `%`와 횟수
- 하단 문구로 "재미용 기록, 포인트 영향 없음" 명시
- 데이터: `death_events`에서 `is_team_kill = 1`인 행을 `killer_account_id` 기준으로 집계

## 4. 총기 `#/weapons`

- 분류 필터 칩: 전체 / AR / DMR / SR / SMG / SG (+ 필요하면 기타)
- 카드: 총기명, 분류, 스쿼드 합계 킬, **이 총의 주인(1위) 강조 박스**, 상위 3명 막대
- 데이터: `death_events.damage_causer` 기준 집계. 팀킬, 자살, AI 대상 킬은 봇의 기존 규칙과 똑같이 제외
- **이름 매핑 필요**: `damage_causer`는 `WeapBerylM762_C` 같은 내부 코드라 표시명과 분류 매핑 테이블 필요 (예: `WeapBerylM762_C → Beryl M762 / AR`). 매핑에 없는 코드는 "기타"로
- API 제안: `GET /api/weapons` → `[{ code, name, category, kills, top:[{ name, accountId, kills }] }]`

## 5. 하이라이트 `#/highlights`

- 상단: 이번 주 좋아요 1위 영상 크게(왼쪽 영상, 오른쪽 설명)
- 목록: 3열 카드(썸네일 16:9, 재생 버튼, 길이, 제목, 주인공, 맵·날짜, 좋아요), 대원별 필터 칩
- 업로드 모달: 파일 드래그 앤 드롭 **또는** 외부 링크(YouTube·치지직 등), 제목, 주인공(대원 선택), 경기 연결(선택)
- 썸네일: 영상에서 추출한 첫 프레임 → 없으면 연결된 경기의 맵 아트
- 구현 메모
  - 업로드는 쓰기 기능이라 **지금의 읽기 전용 API와 분리**하고, `bot.sqlite`가 아닌 별도 저장소(`data/highlights/` 폴더 + `highlights.sqlite` 또는 별도 테이블)를 권장
  - 누구나 올릴 수 없게 최소한의 확인 필요 (예: 디스코드 봇이 발급한 1회용 업로드 코드, 또는 디스코드 로그인)
  - 파일 크기 제한(예: 200MB), 영상 형식 검사, 처음에는 외부 링크만 받는 것도 방법

## 6. 패치노트 `#/patch`

- 왼쪽: 업데이트 타임라인(모바일에서는 가로 스크롤 칩), 오른쪽: 선택한 업데이트 상세
- 상세 구성
  1. 헤더: 날짜·버전, 제목, 요약, 태그(▲버프 ▼너프 ●변경 ↺복각)
  2. **우리 스쿼드 영향** 박스: 우리 데이터(총기 킬 통계)와 패치 대상 총기를 비교해서 자동 생성
     - 예: "가장 많이 쓰는 Beryl M762(214킬)가 너프 대상이에요. 민재만채·델유감 주력 총기예요."
  3. 총기 밸런스: 총기별 카드, 변경 수치 `이전(취소선) → 이후`(상승 초록, 하락 핑크), 한 줄 설명
  4. 복각·돌아온 것들: 카드 3열(맵 아트 + 제목 + 기간)
- 데이터 출처: PUBG 공식 패치노트(공지 페이지)를 사람이 요약해서 JSON으로 넣는 방식이 가장 안정적. 자동 수집을 하더라도 시안의 구조(`weapons[]`, `returns[]`)로 정리해서 저장
- **시안의 패치 내용은 전부 예시**이며 실제 패치 내용이 아님

## 7. 경기 상세 `#/match/:id` (기존 화면 보완)
- 히어로 배경에 그 경기 스크린샷(없으면 맵 아트)을 깔고 어둡게 그라데이션
- 스크린샷이 여러 장이면 히어로 아래에 가로 슬라이더(기존 `initCarousel` 재사용)
- 스크린샷 업로드는 하이라이트와 같은 저장소/인증 방식 사용
